- 화면: 제공된 기본 화면 `public/`(index.html, app.js). 화면 코드는 수정하지 않았습니다.

- 방식: 모든 상태 변경은 화면 버튼을 **실제로 클릭**해서 수행했습니다(계정 버튼 → 로그인, 참가 신청, 신청 취소, 참가 승인, 사유 입력 + 승인 취소, 최신 정보 새로고침, 변경 이력 보기). API를 직접 호출해 상태를 바꾼 단계는 없습니다.
- 계정 분리: alice·bob·charlie·manager1·manager2마다 **별도의 브라우저 컨텍스트**(쿠키·저장소·메모리가 분리된 창)를 사용했습니다. 이 화면은 토큰을 JS 메모리에만 두므로 컨텍스트끼리 로그인이 섞이지 않습니다.
- 화면 표기: 상태 배지는 `승인 대기`=PENDING, `참가 승인`=APPROVED, `대기 취소`=CANCELLED, `승인 취소`=REVOKED입니다. 이력의 행위자는 사용자 ID로 표시됩니다(#1 alice/민지, #2 bob/준호, #3 manager1/운영자 A, #4 manager2/운영자 B, #5 charlie/서연).
